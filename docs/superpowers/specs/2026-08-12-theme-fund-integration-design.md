# 主题研判与基金产品库整合设计

## 目标

本次迭代完成三个用户可见目标：恢复基金产品库的完整可用性；将产品入口“五主题研判”统一更名为“主题研判”；在每个主题详情中展示可追溯的相关公募基金及规则化简析。

本期不建设历史数据回填，不生成个性化投资建议，也不使用大模型自由撰写基金评价。

## 产品结构

应用保留两个一级工作区：

1. **主题研判**：默认入口，展示首批五个主题的机会评分、置信度、证据、历史状态和相关基金。
2. **基金产品库**：保留原有基金搜索、分类筛选、排序、列表/卡片视图和基金详情能力。

导航与页面标题统一使用“主题研判”和“主题研判总览”。页面说明使用“当前聚焦五个首批主题”，避免将主题数量固化为产品名称。主题名称中，“红利”显示为“红利基金”，“债券”显示为“债券基金”。

两个工作区使用同一应用壳，但保持各自数据状态和页面布局独立。来回切换不应导致基金筛选条件、视图偏好或有效缓存丢失。

## 基金产品库恢复

基金产品库继续优先读取同源 `/funds_active.json`，并使用 `/funds_excluded.json` 约束外部降级数据。恢复工作的验收范围包括：

- 顶部入口可点击并正确显示基金产品库；
- 基金数据能正常加载，搜索、分类筛选、排序和视图切换可用；
- 加载、空结果、缓存降级和请求失败均有明确提示；
- 从主题相关基金跳转后，基金产品库能自动定位对应基金或主题搜索词；
- 桌面端与移动端均可在两个工作区之间往返切换。

基金产品库故障不得拖垮主题研判页面，反之亦然。

## 主题相关基金

### 数据来源

主题详情并行读取：

- `/data/five-themes/scores.json`
- `/data/five-themes/scenarios.json`
- `/data/five-themes/fund-links.json`
- `/funds_active.json`

前端按六位基金代码连接主题映射与基金主数据。主题评分和情景数据仍由现有模块处理，基金连接与展示逻辑放入独立的数据函数，避免扩大主题组件职责。

### 展示规则

每个主题默认展示最多五只代表性基金，并提供“查看全部相关基金”入口。排序依次考虑：

1. 人工审核映射优先于自动规则映射；
2. 匹配置信度从高到低；
3. 基金主数据完整度；
4. 基金代码作为稳定兜底排序。

首版不使用收益高低作为推荐排序，避免将历史表现误读为产品推荐。

每只基金展示：基金名称、基金代码、基金类型、匹配方式、匹配置信度和规则化简析。有可靠公开字段时补充阶段收益、规模、成立日期等；字段缺失时显示“暂无公开数据”，不得推测或补造。

### 规则化简析

简析只允许引用已加载字段和主题匹配规则，例如：

- “名称及类型命中黄金主题规则，属于自动匹配，待人工复核。”
- “当前数据包含近一年收益，但缺少规模字段，暂不进行规模比较。”
- “该产品属于债券基金；具体短债、纯债、混合债、可转债或债券 ETF 分类以公开类型字段为准。”

简析末尾统一声明“仅用于产品研究，不构成投资建议”。不得生成买入、卖出、目标收益或确定性预测。

### 债券基金分层

债券主题的候选数量较大，展示时按公开名称和类型字段划分：短债、纯债、混合债、可转债、债券 ETF、其他债券基金。无法可靠分类时归入“其他债券基金”，不得强行分类。

### 空状态与降级

- `fund-links.json` 不可用：主题证据继续显示，相关基金区域显示“主题基金映射暂不可用”。
- 基金主数据不可用：显示基金代码、匹配方式和置信度；名称和分析字段标记不可用。
- 某主题无可靠候选：显示“暂无经规则匹配的相关基金”，不跨主题凑数。

## 交互

用户展开主题卡片后，在证据和历史状态下方看到“相关基金”。点击单只基金或“查看全部相关基金”会切换到基金产品库，并传递基金代码或主题搜索条件。基金库应显示可清除的来源条件，用户可以继续搜索和筛选。

本期使用应用内部状态切换，不新增复杂路由系统。页面刷新仍回到默认的主题研判入口。

## 测试与验收

实施遵循测试先行：

1. 数据单元测试覆盖主题映射与基金主数据联表、排序、缺失字段、空状态和债券分层。
2. 组件/浏览器测试覆盖新名称、主题展开、相关基金展示、跳转基金库以及工作区往返切换。
3. 原基金产品库测试继续覆盖搜索、筛选、排序、缓存和降级逻辑。
4. Vite 生产构建必须通过。
5. Vercel Preview 必须完成构建，并由部署日志确认发布的是 `dist` 产物。

## 非目标

- 不导入历史主题数据；
- 不改变现有评分与情景算法；
- 不提供个性化基金推荐；
- 不引入付费数据源；
- 不自动合并 PR 或发布到生产环境。
