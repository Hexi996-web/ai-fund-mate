# AI虚拟产品经理 V2 设计

## 目标

将现有 AI Fund Mate 升级为“AI虚拟产品经理”，完整展示当前增强数据集已有的真实字段，增加存续过滤、基金分类、组合搜索、真实字段排序和响应式卡片/列表视图。暂不展示或模拟基金规模、基金经理和成立日期。

## 数据口径

- 主数据源为构建生成的 `/funds_active.json`，原始 `funds_simple.json` 仅作降级兜底。
- 页面统计的是基金份额代码数量，不将 A/C 等不同份额合并为基金主体。
- 页面同时给出中国基金业协会最近已核实的基金主体参考数及统计日期，明确两种口径不可直接比较。
- 单条增强记录支持 `code`、`name`、`type`、`netValue`、`dailyChangePercent`、`lastNetValueDate`、`purchaseStatus`、`redemptionStatus`、`operationStatus`。

## 数据过滤与标准化

加载后依次执行格式校验、字段标准化、去重和存续过滤。明确终止、清算、已清盘、终止上市，或运作状态为 `terminated`、`suspected_terminated` 的记录被排除。没有净值的记录仅在活跃快照能够确认其仍活跃时保留；超过 60 天没有净值更新且不活跃的记录由离线数据任务排除。

主数据源失败时退回简化 API。降级数据不伪造净值、涨跌幅、状态或日期，缺失字段显示 `--`，页面提示数据源已降级。

## 分类

分类为全部、股票型、混合型、债券型、货币市场、FOF、其他。优先判断真实 `type`，再用基金名称补充。匹配顺序为 FOF、货币市场、股票型、混合型、债券型、其他，以避免复合名称被较宽泛的关键词提前捕获。

## 搜索、分类与排序

处理链固定为：标准化数据 → 存续过滤 → 300ms 防抖搜索 → 分类过滤 → 排序。搜索同时匹配代码和名称，可与分类组合使用。

只提供已有真实字段的排序：默认顺序、日涨跌幅高低、单位净值高低、最新净值日期新旧、基金代码升降。缺失值始终排在末尾，排序不得修改原始数组。

## 状态与缓存

页面使用局部 React 状态管理 `funds`、查询、分类、排序、加载状态、数据日期、来源和视图模式。派生列表使用 `useMemo`，无需引入全局状态库。

基金缓存升级到 `ai-fund-mate:funds:v3`，结构包含 `schemaVersion`、`date`、`fetchedAt`、`source` 和 `funds`。只复用当日且版本正确的缓存。解析失败时删除损坏缓存并重新请求。视图、分类和排序偏好与基金数据分开保存，避免数据刷新覆盖用户偏好。

## AI 同事文案

优先级为加载/错误、无结果、搜索结果、分类结果、正常就绪。分类状态显示“已筛选出 X 只[分类名]基金份额”；搜索与分类共同生效时显示当前组合条件的结果数量。降级数据源和过期缓存分别显示非阻塞提示。

## 组件与界面

页面拆分为 `AssistantHeader`、`SearchBar`、`CategoryFilters`、`FundToolbar`、`FundCard`、`FundTable`、`StatusBadge`、`SkeletonView` 和 `EmptyState`。标题精确改为“AI虚拟产品经理”。

桌面端默认列表，移动端默认卡片；用户切换后记住选择。两种视图展示相同字段。移动端状态标签允许换行，长名称截断或自然换行，不产生横向溢出。列表使用语义化表格，排序和视图控件具有可访问标签。

## 数据源升级评估

当前免费管线适合每日净值、涨跌幅、申赎与活跃状态。基金规模、经理、成立日期需要新的批量基础资料来源。逐份额抓取东方财富详情请求量大且容易限流；商业数据源更稳定，但需要授权、费用和服务端密钥代理。本版本不模拟这些字段，后续单独设计增量、低频的详情数据任务。

## 验证

单元测试覆盖字段标准化、存续过滤、分类优先级、组合搜索、排序缺失值、缓存版本和损坏缓存。构建验证使用 `npm run build`。页面验证覆盖加载、分类、搜索、排序、视图偏好、移动端布局、降级提示和控制台错误。
